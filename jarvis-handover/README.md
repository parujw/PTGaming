# Jarvis ส่งเวร

พูดครั้งเดียว ทั้งกะรู้เรื่อง: แอปส่งเวร Front Office ที่ฟังเสียง แยกเป็นรายการด้วย Claude แล้วส่งบรีฟเข้ากลุ่ม LINE พร้อมบันทึกว่าใครตอบ "รับ" แล้ว

## ทำอะไรได้
- **คุยกับ Jarvis** พูดหรือพิมพ์สั่งงานได้เลย เช่น "1208 VIP มาบ่ายสามครึ่ง", "915 ซ่อมแอร์เสร็จแล้ว", "เปลี่ยน 712 เป็นด่วน", "มีอะไรค้างบ้าง", "ส่งบรีฟทั้งกะ" ทุกอย่างที่ Jarvis ทำมีปุ่มย้อนกลับ ส่วนการส่ง LINE ต้องกดยืนยันเอง
- **ติ๊กงานเสร็จ** แตะวงกลมหน้ารายการบนบอร์ด (มีปุ่มย้อนกลับ 5 วินาที) ระบบจำว่าใครปิด
- **พูดได้หลายเรื่องในครั้งเดียว** แตะปุ่มทองแล้วเล่าได้หลายห้อง (Chrome/Android/Edge และ Safari บน iOS ที่รองรับการฟังเสียง) เบราว์เซอร์ที่ฟังเองไม่ได้ ใช้ปุ่มไมค์บนคีย์บอร์ดแทน
- **Jarvis สรุป** Claude แยกเป็น ห้อง · แขก (ย่อตาม PDPA) · หมวด · ความด่วน · สิ่งที่ต้องทำ · เวลา
- **หน้า "งานที่ต้องทำต่อ"** รายการเดียว เรียงตามสิ่งที่ต้องทำก่อน: ทำทันที (ด่วนหรือเลยเวลา) → ตามเวลา (เรียงเวลาใกล้สุด) → ติดตามให้จบ → แจ้งให้ทราบ ทุกงานขึ้นต้นด้วยสิ่งที่ต้องทำ ตามด้วยห้อง/แขก/ที่มา และเวลาที่เหลือ ("อีก 40 นาที", "เลย 15 นาที") งานที่เสร็จวันนี้พับไว้ท้ายหน้า บรีฟ LINE ใช้ลำดับเดียวกัน
- **เข้าสู่ระบบด้วยอีเมลและรหัสผ่าน** ทุกงานบันทึกว่าใครแจ้งและใครปิด ผู้ดูแลเพิ่มพนักงาน ตั้งรหัสใหม่ และปิดบัญชีได้ที่ ตั้งค่า > จัดการทีม
- **แจ้งคนที่ส่งเรื่องเมื่อเสร็จ** เมื่อเพื่อนติ๊กงานเสร็จ คนที่แจ้งเรื่องนั้นจะเห็นกระดิ่งแดงและข้อความ "ห้อง X ที่คุณแจ้ง เรียบร้อยแล้ว · โดย Y" ทันที (ถ้าเปิดการแจ้งเตือนของเบราว์เซอร์ไว้ จะเด้งแม้สลับไปแอปอื่น) และถ้าตั้ง LINE OA ไว้ จะโพสต์ "✅ เรียบร้อยแล้ว" ในกลุ่มหลังพ้นช่วงย้อนกลับ 5 วินาที
- **สรุปส่งไลน์** บรรทัดแรกบอกจำนวนเรื่องด่วน เรียงด่วนก่อน ส่งได้ 3 แบบ: ส่งเข้ากลุ่มอัตโนมัติ (LINE OA), เปิดหน้าแชร์ของ LINE, หรือคัดลอก
- **รับเวร** เพื่อนพิมพ์ "รับ" ในกลุ่ม LINE หรือกด "ฉันรับเวรแล้ว" ในแอป ชื่อจะขึ้นใต้บรีฟนั้น
- **ติดตั้งบนมือถือ** เป็นแอป (PWA) เปิดได้แม้สัญญาณหลุด

แอปทำงานได้ 3 ระดับ เปิดเพิ่มทีละขั้นได้:

| ระดับ | ต้องตั้ง | ได้อะไร |
|---|---|---|
| 0 | ไม่ต้องตั้งอะไร | บอร์ดในเครื่อง, Jarvis โหมดพื้นฐาน (เพิ่ม/ปิด/เปลี่ยนความด่วน/ถามเรื่องค้าง/ส่งบรีฟ ด้วยคำสั่งตายตัว), แชร์/คัดลอกเข้า LINE |
| 1 | `ANTHROPIC_API_KEY` + `TEAM_PIN` | Jarvis ใช้ Claude เข้าใจคำสั่งภาษาพูด (ใส่ PIN ในหน้าตั้งค่า) |
| 2 | Firebase | หน้าเข้าสู่ระบบ, บอร์ดเดียวกันทั้งทีมแบบเรียลไทม์, แจ้งคนที่ส่งเรื่องเมื่อเสร็จ |
| 3 | LINE OA | ส่งเข้ากลุ่มอัตโนมัติ และนับคนตอบ "รับ" |

## โครงสร้าง
```
index.html          หน้าแอปทั้งหมด (ไม่มีขั้นตอน build)
config.js           ตั้งค่าฝั่งหน้าเว็บ: teamId และ Firebase web config
api/jarvis.js       POST: บทสนทนา + บอร์ด → คำตอบและ actions (Claude)
api/summarize.js    POST: ข้อความ → รายการส่งเวร (Claude, สำรองไว้ให้ระบบอื่นเรียก)
api/line-push.js    POST: ส่งบรีฟเข้ากลุ่ม LINE
api/line-webhook.js LINE webhook: "jarvis id" ตั้งกลุ่ม, "รับ" บันทึกคนรับเวร
api/users.js        ผู้ดูแล: ดู/เพิ่มพนักงาน ตั้งรหัสใหม่ ปิดบัญชี
api/config.js       GET: บอกหน้าเว็บว่าเปิดฟีเจอร์ไหนไว้
scripts/create-user.mjs  สร้างบัญชีผู้ดูแลคนแรกจาก command line
firestore.rules     ให้เฉพาะอีเมลในรายชื่อทีมอ่าน/เขียนได้
```
แก้สีแบรนด์ที่ตัวแปร `--gold`, `--gold-hi`, `--night` บนสุดของ `<style>` ใน `index.html`

## Deploy

### 1. GitHub
โฟลเดอร์นี้อยู่ใน repo `PTGaming` ตอนนี้ จะใช้ต่อในนี้หรือย้ายไป repo ใหม่ก็ได้ (คัดลอกทั้งโฟลเดอร์ `jarvis-handover/` ไปไว้ที่ root ของ repo ใหม่)

### 2. Vercel
1. New Project → เลือก repo
2. ถ้าใช้ repo `PTGaming` ตั้ง **Root Directory** เป็น `jarvis-handover`
3. Framework Preset: **Other** ไม่ต้องมี Build Command
4. Environment Variables (ดู `.env.example`):
   - `ANTHROPIC_API_KEY` จาก platform.claude.com
   - `TEAM_ID` = `fo`
   - `TEAM_PIN` ตั้งเลขที่ทีมรู้กัน (ถ้ายังไม่ใช้ Firebase)
5. Deploy แล้วเปิดเว็บ → ตั้งค่า → ใส่ชื่อและ PIN

### 3. Firebase (บัญชีพนักงาน + บอร์ดร่วมทั้งทีม)
1. สร้างโปรเจกต์ที่ console.firebase.google.com
2. **Authentication** → Sign-in method → เปิด **Email/Password** และเพิ่มโดเมน Vercel ใน Authorized domains
3. **Firestore** → Create database (production mode, region `asia-southeast1`)
4. Project settings → Your apps → Web → คัดลอก config ไปวางใน `config.js` (ค่านี้ไม่ใช่ความลับ)
5. Project settings → Service accounts → Generate new private key → วาง JSON ทั้งก้อนใน Vercel เป็น `FIREBASE_SERVICE_ACCOUNT` (อย่า commit ไฟล์นี้)
6. Deploy rules:
   ```bash
   npm i -g firebase-tools
   firebase login
   firebase use --add          # เลือกโปรเจกต์
   firebase deploy --only firestore:rules
   ```
7. สร้างบัญชีผู้ดูแลคนแรก (ครั้งเดียว) จากเครื่องที่มีไฟล์ service account:
   ```bash
   npm install
   FIREBASE_SERVICE_ACCOUNT="$(cat service-account.json)" TEAM_ID=fo \
     node scripts/create-user.mjs <อีเมล> '<รหัสผ่าน>' "<ชื่อ>" admin
   ```
   จากนั้นเข้าแอป → ตั้งค่า → จัดการทีม เพื่อเพิ่มพนักงานคนอื่น แล้วเปลี่ยนรหัสผ่านของตัวเองที่ ตั้งค่า → เปลี่ยนรหัสผ่าน

### 4. LINE Official Account (ส่งอัตโนมัติ)
LINE Notify ปิดบริการแล้ว จึงใช้ Messaging API
1. สร้าง LINE Official Account และเปิด Messaging API ที่ developers.line.biz
2. ในหน้า Messaging API: เปิด **Allow bot to join group chats**, ปิด Auto-reply
3. Webhook URL: `https://<โดเมน-vercel>/api/line-webhook` แล้วเปิด Use webhook
4. ใส่ใน Vercel: `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET`
5. เชิญบอทเข้ากลุ่มส่งเวร แล้วพิมพ์ `jarvis id`
   - ถ้าตั้ง Firebase แล้ว บอทจำกลุ่มให้เอง
   - ถ้ายังไม่ตั้ง บอทจะตอบ Group ID ให้นำไปใส่ `LINE_GROUP_ID`
6. Redeploy บน Vercel ปุ่ม "ส่งเข้ากลุ่มทีม" จะขึ้นแทน "เปิดใน LINE" ในหน้าสรุปส่งไลน์

## ความปลอดภัยและ PDPA
- API ทุกตัวต้องมี Firebase ID token ของสมาชิกทีม หรือ PIN ทีม ถ้าไม่ได้ตั้งทั้งสองอย่าง API จะปฏิเสธ
- Webhook ตรวจลายเซ็น `x-line-signature` ทุกครั้ง
- AI ถูกสั่งให้ย่อชื่อแขก ไม่ใส่เบอร์โทร อีเมล เลขพาสปอร์ต หรือเลขบัตร แต่ยังควรตรวจก่อนส่งทุกครั้ง
- ข้อความที่พูดถูกส่งไปประมวลผลที่ Anthropic API และบรีฟถูกส่งผ่าน LINE ควรตรวจนโยบาย IT ของโรงแรมก่อนใช้กับข้อมูลแขกจริง
